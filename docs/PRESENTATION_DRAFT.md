## 0. 한 줄 정의

**FP 모닝 브리핑** — 5분마다 바뀌는 회전 QR로 FP의 출퇴근을 기록하고,
지점장의 아침 10분을 AI가 정리해 주는 무비용 출근관리·운영 어시스턴트.

---

## 1. 왜 만들었나

### 1.1 현장에서 본 문제

- **NFC 카드 출퇴근**: 회사 차원에서 운영 중. 연간 3천만원 추정.
  사실상 "찍기"만 됨. 누가 왜 안 나왔는지, 평소랑 뭐가 달라졌는지에 대한 정보는 0.
- **종이 출근부 / 단톡방 인증**: 대리 출석 천국. 시간 검증 안 됨. 집에서도 보냄.
- **본사 그룹웨어 출근**: PC 켜야 가능. 매일 외근하는 FP 직군 동선과 안 맞음.
- **고정 QR 코드 출력해 붙여두기**: 한 번 캡처되면 단톡방으로 공유 끝.

→ "기존 도구는 비싸거나, 부정 출석을 못 막거나, FP 직군에 안 맞거나" 셋 중 하나였음.

### 1.2 지점장 입장에서 진짜 필요한 것

- 100명짜리 지점장이 아침 9시 5분에 알고 싶은 건
  "오늘 누가 안 나왔는지" + "그게 평소랑 다른 일인지" 두 가지.
- 출퇴근 시각만 쌓이는 데이터로는 그 질문에 답할 수 없음.
- 데이터를 **모으는 것**이 아니라 **읽어서 행동을 제안하는 것**이 진짜 가치라고 봤음.

### 1.3 시작 — 작게, 운영비 0으로, 본사 결재 없이

- 본사 IT 결재 라인 안 타고 지점 자체로 도입 가능하게 설계.
- 운영비 한 푼도 안 들이고 **실제로 돌아가는** 것을 먼저 증명한 뒤,
  거기서 얻은 데이터로 본사·지점장에 제안하는 순서로 접근.
- 처음에는 정발산 육성센터에 도입해서 **종이 출근부 폐지**.
- 두 달 운영하면서 안정화 → 2026 한화손보 바이브코딩 경진대회 출품용 v2로 확장.

## 2. 이거 어떤 점이 좋은가 (핵심 4가지)

### 2.1 예산 — 운영비 월 0원

| 항목 | 비용 | 비고 |
|---|---|---|
| 호스팅 (Vercel) | 0원 | 정적 페이지, 무료 플랜 |
| 백엔드 (Google Apps Script) | 0원 | 회사 구글 계정으로 동작 |
| DB (Google Sheets) | 0원 | 사용량 한도 안에 안전하게 들어옴 |
| QR / TOTP | 0원 | 표준 알고리즘, 라이브러리 무료 |
| AI 브리핑 (Claude Haiku) | 약 월 수천 원 추정 | 지점당 하루 1~2회 호출, 토큰 단가 낮음 |
| **합계** | **사실상 0원** | 회사 결재·예산 라인 없이 즉시 도입 가능 |

비교 대상: 현재 회사 NFC 카드 출퇴근 시스템 **연 약 3천만원**.

### 2.2 기능 — 기존 시스템 대비 훨씬 많음

기존 NFC는 출퇴근 시각만 찍힘. 본 시스템에는:

- 4가지 이벤트 (출근 / 귀소 / 학습회 / 퇴근)
- **AI 모닝 브리핑** — 지점장 화면 상단에 "오늘 누구 확인하세요" 한 단락
- **결근 분류** — "갑자기 결근(평소 출근율 70%↑인데 오늘 결근)" vs "장기 미출근(최근 5영업일 0회)" 자동 분리
- **개인 출근 시간 변화 추적** — 평소 대비 30분 이상 차이나면 자동 감지
- **14영업일 추세 그래프** — 출근 인원 추이를 한눈에
- **공휴일 자동 감지** — 출근 0명 영업일은 평균에서 자동 제외
- **휴가/외근/교육 메모** — 지점장이 한 번 등록하면 결근 분류에서 자동 제외
- **streak 카드 (FP 화면)** — "N일 연속 출근", "이번달 누적", "지난주 매일 출근" 개인 동기부여
- **AI 인사말 (FP 화면)** — 출근 시 한 문장 인사 ("오늘도 깔끔하게 시작" 같은 톤)
- 일일·월간 리포트 메일 자동 발송 (CSV 첨부)
- 수기 입력 + 모든 수정에 사유 필수 + 감사 로그

### 2.3 실제 돌아간다 — 운영 2개월 검증

- 첫 커밋 2026-04-17, 현재 2026-06-08 — **약 2개월 운영**.
- 정발산 육성센터 실제 운영 중. 종이 출근부 사용 0건으로 대체.
- 그동안 잡힌 실제 버그·UX 이슈 60여 건 → 운영 중에 모두 수정 반영.
  (사번 타입 불일치, 시트 Date 객체 변환, QR 갱신 주기 등 — 현장 데이터로만 발견되는 문제들)
- **듀얼 호스팅 구조**: 운영용 v1 (GitHub Pages) + 대회 출품 v2 (Vercel).
  같은 시트·같은 GAS 백엔드를 공유하지만, v2 신기능을 자유롭게 만들어도 정발산 운영에는 영향 0.
- 코드 규모: **약 6,700줄, GAS 함수 70여 개**. 이미 PoC 수준 넘어선 상태.

### 2.4 확장성 — 지점장 도입 시 진짜 가치 나옴

- **현재 적용**: 정발산 육성센터 (소규모, 안정화 검증용).
- **즉시 확장 가능**: 지점장. **100명 규모 지점 운영자**에게 가장 효과적.
  - 100명 출근 현황을 매일 일일이 다 볼 수는 없음.
  - AI 브리핑이 "오늘 이 3명만 확인하세요" 한 줄로 정리해 줌.
  - 이게 NFC·종이 출근부에서는 절대 안 나오는 정보.
- **그 위로**: 본부장·지역단장은 빵가루 네비로 산하 모든 지점 합산 카드 자동 조회.
  4계층 조직도(본부→지역단→지점→사업소)가 이미 256개 노드 구축되어 있어 추가 작업 없음.

## 3. 세부 기능 — 어떻게 동작하나

### 3.1 시스템 구조 한 장 그림

```
[ 태블릿 ] ──────────► [ FP 폰 ] ──────────► [ 지점장 PC ]
display.html         checkin.html          admin.html
5분 회전 QR          사번/이름 등록          AI 브리핑 + KPI
                      4가지 이벤트            추세 그래프
                                              결근 분류
        │                  │                       │
        └────── HTTPS ─────┴───────────────────────┘
                           ▼
                  Google Apps Script
                  (TOTP 검증, AI 호출,
                   조직도 탐색, 상태 판정)
                           ▼
                    Google Sheets
                  (출석로그·조직도·토큰·
                   지점설정·지점장메모·감사)
```

### 3.2 핵심 메커니즘 — 회전 QR (TOTP)

**왜 이게 중요한가**: 고정 QR을 출력해 붙여두면 한 번 캡처가 카톡에서 영원히 살아남음. 본 시스템 QR은 **5분마다 바뀜**. 캡처해서 단톡방에 뿌려도 5분 뒤면 무용지물.

- 알고리즘: HMAC-SHA256 기반, RFC 6238 변형. 표준 OTP와 같은 원리.
- 윈도우: 300초 (5분), Grace 30초 (시계 오차 보정).
- 브라우저는 Web Crypto API로, 서버는 GAS `Utilities.computeHmacSha256Signature`로 **같은 코드 생성·검증**.
- QR이 갖고 있는 정보: `?code=6자리&t=시각&branch=지점코드`.

### 3.3 디바이스 토큰 바인딩 — 1인 1기기

- FP가 첫 등록 시 사번·이름 입력 → UUID 토큰 발급.
- 토큰은 폰의 localStorage + 서버 시트에 각각 저장.
- 다음부터는 같은 폰에서 사번 입력 없이 자동 인증 → **2초 안에 출근 완료**.
- **다른 폰에서 같은 사번으로 등록 시 이전 토큰 자동 삭제** → 폰 교체는 자동 대응.
- 관리자가 사번 기준으로 토큰 강제 초기화 가능 → 폰 분실 대응.

### 3.4 4계층 조직도 (single source of truth)

- 본부 → 지역단 → 지점 → 사업소. **256개 노드** 미리 구축.
- code 구조 자체에 경로가 녹아있음 (`seoul.gangbuk.sudo.gwanak`).
- 본부장이 본부 코드로 들어오면 BFS로 산하 모든 지점·사업소 출석 자동 합산.
- 권한 분리도 같은 트리로 — 다른 본부 사번은 기기 초기화 못함.

### 3.5 FP 화면 (checkin.html) — 폰에서 보는 화면

- 진입: 태블릿 QR 카메라 스캔으로만 (직접 URL 접근 불가).
- 등록 안 된 첫 사용자: 사번·이름 → 등록 정보 확인 화면 → 출근.
- 등록된 사용자: 사번 입력 없이 자동 인증, 본인 이름으로 환영 + AI 한마디.
- **streak 카드**: "3일 연속 출근", "이번달 12일 누적", "지난주 매일 출근" 등 자동 표시.
- **이번주 출근 5칸**: 월~금 동그라미로 어느 요일 나왔는지 시각화.
- **4가지 이벤트 그리드**:
  - 출근 (오전, 한 번)
  - 귀소 (14시 이후만 활성화 — 오전 출근 직후 못 찍음)
  - 학습회
  - 퇴근
- AI 인사말은 **타이핑 애니메이션**으로 한 글자씩 표시 (Pretendard 폰트).

### 3.6 태블릿 화면 (display.html) — 지점 입구에 비치

- 네이비 풀스크린 + 흰 QR 카드 + 오렌지 corner brackets (한화 BI 톤).
- 큰 시계, 지점명 배지, "QR 갱신까지 N:NN" 타이머 바.
- 매 1초 시계·타이머 갱신, QR은 5분 윈도우 바뀔 때만 다시 렌더링 (성능).
- 인터넷만 연결돼 있으면 사람 손 안 가게 동작.
- 전체화면 버튼 1개 — 태블릿 한 번 세팅하면 끝.

### 3.7 관리자 화면 (admin.html) — 지점장이 매일 아침 보는 화면

상단부터 차례로:

1. **빵가루 네비**: 서울본부 > 강북지역단 > 수도지점 (클릭으로 상위 이동).
2. **AI 모닝 브리핑 카드** (풀너비 단색 네이비).
3. **14영업일 출근 추세 그래프** (SVG sparkline, 각 점 위 인원 숫자, 평균선, 공휴일은 회색 점).
4. **KPI 4종**:
   - 출근 (오늘 인원 + 평소 대비 변동)
   - **결근 (갑자기)** — 클릭 시 명단 모달 (사진·평소 출근율·마지막 출근일·"사유 등록" 버튼)
   - 지각
   - **장기 미출근** — 클릭 시 명단 모달
5. 일별 테이블 (정렬·필터 가능, 사업소별 필터, 메일 전송 버튼).

탭 6개:
1. 일일 현황 (위 내용)
2. 월간 리포트 (평균 출근일·시간·정상률)
3. 주목 알림 (3일 이상 연속 미출근 자동 탐지)
4. 수기 입력 + 수정 이력
5. QR 세팅 (지점별 태블릿 URL 자동 생성·복사 + 지점 GPS 등록 옵션)
6. 기기 초기화 (분실폰 대응)

권한별 자동 분기:
- 본부장·지역단장 레벨 → 산하 지점 요약 카드 + 수기/QR세팅/기기초기화 탭 자동 숨김.
- 지점장 레벨 → 사업소 필터 활성화.

### 3.8 AI 모닝 브리핑 — 가장 핵심적인 차별화 요소

**왜 이게 NFC와 다른가**: NFC는 "데이터"만 줌. 본 시스템은 데이터를 읽어 **"오늘 무엇을 하라"** 까지 제안.

**서버가 자동 집계하는 입력 데이터** (지점장이 손가락 하나 안 댐):
- 오늘 출근 N명 vs 평소 평균(14영업일) → 변동치
- 지난달 평균과 비교
- 같은 요일 4주 평균 (월요일은 월요일끼리 비교)
- 시간대 분포 (8시 전 / 8~8:50 / 8:50~9시 / 9시 이후)
- **평소 잘 나오는데 오늘 결근**한 사람 명단 (출근율 70%↑인데 오늘 결근)
- **개인 출근 시간 큰 변화** (평소 대비 ±30분 이상)
- 휴가·외근·교육 등록자 (분류에서 자동 제외)
- 장기 미출근자 수

**AI에게 시키는 일**:
- 모델: Claude Haiku 4.5 (저비용·저지연)
- 시스템 프롬프트: "Korean insurance branch manager용 chief-of-staff 브리핑. 변화 1~2개 + 행동 제안 1개. '화이팅' 같은 클리셰 금지. 이모지 금지."
- 출력 길이: 3~4문장, 최대 220자.

**예시 출력** (실제 톤):
> 오늘 출근 28명, 평소 31명 대비 -3.
> 김OO, 박OO 평소 출근율 90% 이상인데 오늘 둘 다 결근.
> 오전 중 한 번 전화 확인 권장.

이게 NFC 대비 진짜 차이.

### 3.9 결근 분류 시스템

지점장이 매일 받는 가장 큰 인지 부담은 "이 사람 결근이 평소대로인가, 평소랑 다른가" 판단임. 시스템이 자동 분류:

- **갑자기 결근 (unusual)**: 최근 30영업일 출근율 70% 이상인데 오늘 결근.
  → 평소 잘 나오시던 분이 안 보임 = 진짜 확인 필요.
- **장기 미출근 (long term)**: 최근 5영업일 0회 출근.
  → 이미 며칠째 안 보이는 상태 = 별도 액션 필요.
- **사유 등록자 (제외)**: 휴가·외근·교육·기타. 지점장이 한 번 등록하면 그 날짜는 결근 분류에서 자동 제외.
  → 매일 같은 이유로 결근 알람 안 받게.

명단 모달에는 출근율 컬러 pill (80↑ 그린 / 60~80 노랑 / 60↓ 빨강) + "그제·N일 전" 상대 시간 표시.

### 3.10 출근 상태 판정 — Late Binding 설계

- 출근 시각만 기록하고 **상태(정상/지각/근무중)는 저장 안 함**.
- 조회 시점에 그날 지점의 마지노선(예: 09:00 정상, 10:00 지각)과 비교해 판정.
- **장점**: 지점장이 마지노선을 바꾸면 **과거 데이터까지 즉시 재집계**. 마이그레이션·재기록 불필요.
- 지점에 설정 없으면 상위 본부 설정 자동 상속. 둘 다 없으면 시스템 기본값.

### 3.11 보안 모델 — 막을 수 있는 것과 못 막는 것 (솔직히)

**막는 것**:
- 1시간 뒤 캡처 QR 재사용 → 5분 윈도우 만료로 차단
- 두 폰 동시 출근 → 토큰 자동 교체로 이전 폰 무효화
- 1초 100번 연타 → 1분 중복 체크
- 권한 없는 본부 데이터 조회 → 조직 코드 BFS 권한 분리
- 데이터 무단 수정 → 모든 수정에 사유 필수 + 별도 감사 로그 시트

**현재 못 막는 것 (솔직히 발표 시 인정 권장)**:
- 시크릿 키가 클라이언트 코드에 노출 → 로드맵에 서버 측 이동.
- 5분 윈도우는 단톡방 공유에 충분한 시간 → 60~90초로 단축 검토.
- 위치 검증은 **옵션**으로만 구현 (운영 강제는 안 함, 좌표 등록한 지점만 동작).
- admin 페이지는 비밀번호 게이트 1개뿐 → Google OAuth 도입 검토.
- HR 마스터 시트 없음 → 임의 사번 등록 가능.

→ 이 부분은 발표 시 **"우리가 막은 것 / 아직 못 막은 것"** 을 솔직히 구분해서 보여주는 게 신뢰도에 좋음.

### 3.12 기술 스택과 그 선택 이유

| 영역 | 선택 | 왜 |
|---|---|---|
| 프론트 | 바닐라 HTML/CSS/JS | 페이지 3개라 React/Vue 빌드 파이프라인 오버킬 |
| QR | qrcode.js | 작고 검증된 라이브러리 |

### 3.13 디자인 시스템

- **컬러**: 한화 BI 오렌지 `#FF6600` + 네이비 `#001E4E`.
  CTA는 오렌지, AI 영역·QR display 헤더는 네이비.
- **화면 원칙**:

## 4. 내가 이걸 만들 수 있었던 이유

### 4.1 학습 이력 — 비전공자, 자력으로

- **노션**: 업무 자동화·DB 활용. 내부 자료 정리 체계 직접 구축.
- **파이썬**: 자동화 스크립트. 반복 업무 시간 단축.
- **클로드 코드 (Claude Code) 바이브코딩**: AI와 페어 프로그래밍.
  - 본 시스템도 클로드 코드와 함께 만든 것.
  - "코드를 다 외워서 짜는 사람"이 아니라 "AI에게 정확히 무엇을 시킬지 아는 사람"이 새로운 개발자상이라는 걸 직접 체득.

### 4.2 팀 내 AI 교육 진행

- 팀원 대상으로 AI 활용 교육 실시.
- 단순 ChatGPT 사용법이 아니라 **"우리 업무에 어떻게 접목할지"** 중심.
- 본 시스템은 그 교육의 산물이자 효과 증명.

### 4.3 그래서 무엇을 시사하나

- **본사 IT 부서를 거치지 않아도** 현장 단위로 운영 시스템을 자력 구축할 수 있는 시대.
- AI + 무료 클라우드 서비스(GAS, Sheets, Vercel) 조합 = 운영비 0원으로 작동.
- 회사 차원에서 이 역량을 다른 지점·부서로 확산하면
  → 본사 IT 백로그 부담 ↓, 현장 자율성 ↑, 도입 속도 ↑.
- "AI 시대의 현장 운영자상"을 정발산 케이스로 먼저 증명한 결과.

## 6. 발표할 때 자주 받을 만한 질문 (예상 Q&A)

**Q. 보안은 괜찮나?**
A. 5중 방어선(회전 QR + 디바이스 토큰 + 중복 차단 + 권한 분리 + 감사 로그)으로 NFC 대비 부족하지 않다. 단, 시크릿 키 노출·관리자 OAuth 미적용은 현재 한계이며 로드맵에 명시 — 운영 단계별로 강화 가능.

**Q. 회사 시스템과 충돌하지 않나?**
A. 본사 NFC와 별개로 동작. 지점 자체 운영 도구 성격이라 본사 IT 결재 라인 안 탐. 필요 시 본사 HR 시스템과 연동 가능한 구조로 설계됨.

**Q. 만약 GAS·시트가 한도 도달하면?**
A. 사번 1만 명 × 250영업일 × 2회 = 500만 셀. 1년 이상 누적 시 시트 분할(이미 archive 함수 구현됨) 또는 BigQuery 이전 가능. 현 규모에선 충분.

**Q. AI 응답 비용은?**
A. Claude Haiku 4.5 호출 1회당 토큰 비용 매우 낮음. 지점당 하루 1~2회 호출 가정 시 월 수천 원 수준 추정.

**Q. 차장님 본업은 뭔데 이런 걸 만드나?**
A. (차장님이 답할 영역) 노션·파이썬·클로드 코드 자력 학습 + 팀 내 AI 교육 진행 경험. 현장에서 본 문제를 현장에서 풀어보는 시도.

**Q. 다른 지점도 도입하려면 뭐가 필요한가?**
A. 태블릿 1대 + 인터넷 + 지점 코드 1줄. QR 세팅 탭에서 URL 자동 생성·복사 → 태블릿 브라우저에 붙여넣기 → 끝. 본사 결재 없이 지점장 판단으로 즉시 도입 가능.
